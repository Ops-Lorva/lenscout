# Lenscout v1 — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** une app de bureau (macOS, Linux, Windows) qui découvre les caméras IP d'un réseau, les active, règle IP/NTP/fuseau sans leur page web, et affiche leur flux pour le cadrage — Axis d'abord, Hikvision/LTS ensuite.

**Architecture :** un workspace Cargo calqué sur LanProbe : `crates/lenscout-core` (toute la logique, sans Tauri, testée sans caméra) et `src-tauri` (commandes Tauri minces), plus un front SvelteKit statique. Tout ce qui touche le réseau passe par trois traits (`CameraHttp`, `Datagram`, `Elevator`) ; les tests les remplacent par des faux et les parsers se testent sur des fixtures d'octets.

**Tech Stack :** Rust édition 2024, Tauri 2, SvelteKit + Svelte 5 + svelte-i18n, vitest ; crates `reqwest` (rustls), `digest_auth`, `hickory-proto`, `quick-xml`, `socket2`, `keyring` 3, `async-trait`, `tokio-util`, `uuid`, `thiserror`, `minisign-verify`.

**Spec :** `docs/specs/2026-11-13-lenscout-design.md`

Chaque fichier copié porte en tête `// Repris de LanProbe <chemin> le <date>`.

## Décision : affichage du flux

**MJPEG tiré par Rust** (Axis `GET /axis-cgi/mjpg/video.cgi`, Hikvision `GET /ISAPI/Streaming/channels/102/httpPreview`), découpé en JPEG et poussé au webview par un `tauri::ipc::Channel` en octets bruts : aucun codec ni ffmpeg à embarquer, latence d'une image, et l'authentification Digest reste côté Rust, donc le mot de passe n'atteint jamais le webview.

## Global Constraints

- OS : macOS, Linux et Windows **à égalité** ; tout chemin propre à un OS existe pour les trois (`#[cfg(target_os = …)]`), sinon la tâche n'est pas finie.
- Licence MIT ; dépôt public (GitHub Ops-Lorva) — **aucun script de release ni secret dans ce dépôt** : les scripts de secours vont dans `/home/benjamin/projects/LORVA/releases/lenscout` (dépôt privé).
- Langues : fr, en, es ; **chaque** clé existe dans les trois (test de parité de la tâche 1).
- **Aucun mot de passe en clair** dans un fichier de l'app, un journal, une URL ou un message d'erreur. Les mots de passe vivent dans le trousseau (Keychain / Credential Manager / Secret Service) et circulent dans le type `Secret`, qui n'implémente **pas** `Serialize` et dont `Debug`/`Display` affichent `***`. Un mot de passe envoyé à une caméra va dans le **corps** de la requête, jamais dans la query string.
- **L'IP temporaire ajoutée au poste est toujours retirée**, y compris après une erreur ou une panique ; un journal sur disque permet de la retirer au démarrage suivant si l'app a été tuée.
- Une action (unitaire ou en lot) ne touche **que** les caméras sélectionnées, et vérifie l'identité (MAC ou n° de série) de la caméra juste avant d'écrire.
- Interface sobre : **aucun texte explicatif à l'écran** — libellés, valeurs, messages d'erreur d'une ligne. Les explications vont en commentaires de code.
- Style : jetons CSS `--ep-*` repris tels quels de LanProbe `src/app.css`.
- Hikvision/LTS : tout code SADP/ISAPI porte en tête `// NON VÉRIFIÉ sur une vraie caméra LTS — écrit d'après <source>` et le CHANGELOG le dit.
- Autres marques (ONVIF ou préfixe MAC seuls) : liste + « Ouvrir la page web », **aucune** action de configuration.
- Identifiant d'app : `io.lenscout.app` ; produit `Lenscout` ; paquet Rust de l'app `lenscout`, lib `lenscout_lib`.
- Version `0.0.0` dans le dépôt ; la CI et les scripts de release écrivent celle du tag (comme LanProbe).
- Changer l'IP **du poste** : même mécanisme que LanProbe (`configure.rs` + `permissions.rs`), même validation stricte — macOS `networksetup` via `osascript` (ou `sudo -n` si la règle sudoers est posée), Windows `.bat` `netsh` lancé par `run_elevated_bat`, Linux `nmcli`. **Copier et adapter ce code, ne rien inventer d'autre.**
- **Compilation — machine limitée (~12 Go) :**
  - jamais plus de **2 compilations Rust en même temps** (toutes sessions et worktrees confondus) ;
  - `CARGO_TARGET_DIR` **local, hors NFS**. Dans le dépôt principal :
    ```bash
    export CARGO_TARGET_DIR="$HOME/.cache/cargo-target/lenscout"
    cargo test -p lenscout-core          # tâches « core » : ne compile pas Tauri
    cargo build -p lenscout              # tâches qui touchent src-tauri
    ```
    Dans un worktree (un par agent), un dossier par worktree pour éviter le verrou et les recompilations croisées :
    ```bash
    export CARGO_TARGET_DIR="$HOME/.cache/cargo-target/lenscout-wt-<n° de tâche>"
    ```
    et, une fois la tâche fusionnée, renommer ce dossier en `…-a-nettoyer` (pas de suppression par un agent ; disque de HOU-DEV souvent plein) ;
  - `node_modules` d'un worktree = lien symbolique vers celui du dépôt principal (comme LanProbe), pas de second `npm ci`.
- Tests front : `npm test` (= `svelte-check` + `vitest run`). Tests Rust : `cargo test -p lenscout-core` ; `cargo clippy --workspace -- -D warnings` propre à chaque tâche.
- Git : une branche par tâche, jamais de commit direct sur `main` ; messages en français ; dernière ligne de chaque commit : `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Aucun push tant que les dépôts distants n'existent pas.

## Review Focus

1. **Caméra qui change d'IP pendant l'action** (DHCP, autre installateur, lot précédent) : l'action vérifie MAC/série à l'adresse visée et refuse d'écrire si ce n'est plus la bonne caméra → tests dans les tâches 11 et 15.
2. **Une même caméra vue par mDNS, WS-Discovery, SADP et ARP** : une seule ligne, pas quatre ; une réponse sans MAC fusionne par IP → test dans la tâche 8.
3. **Élévation refusée ou annulée** (UAC « Non », mot de passe macOS annulé, polkit refusé) : message d'une ligne « droits refusés : caméra hors du sous-réseau du poste (169.254.x.x) », aucune IP laissée sur le poste → tests dans la tâche 13.
4. **Réponses réseau tronquées ou hostiles** (paquet mDNS coupé, XML mal formé, flux MJPEG sans `Content-Length`, image géante) : jamais de panique, paquet ignoré, tampon MJPEG plafonné → tests dans les tâches 3, 7 et 14.
5. **Plage d'IP qui déborde ou heurte un appareil existant** (`.254` dépassé, passerelle dans la plage, IP déjà prise par un appareil non sélectionné) : erreur dans l'aperçu, rien n'est appliqué → tests dans la tâche 15.

### Tâche 2 : Marque par préfixe MAC et recherche MAC / n° de série

**Objectif :** reconnaître la marque d'une caméra par son OUI, et filtrer la liste par ce qui est imprimé sur la boîte.

**Files :**
- Create : `crates/lenscout-core/data/oui.tsv` (copie de LanProbe), `src/lib/search.test.ts`
- Create : `src/lib/search.ts`
- Modify : `crates/lenscout-core/src/oui.rs` (stub → copie de LanProbe + ajout)

**Interfaces :**
- Consumes : `model::{Family, normalize_mac}` ; `api/types.ts::Camera`.
- Produces : `oui::vendor_for_mac(mac: &str) -> Option<String>` (copié) ; `oui::camera_brand_for_mac(mac: &str) -> Option<(Family, String)>`. `search.ts` : `normalizeQuery(q: string): string`, `matchesCamera(c: Camera, q: string): boolean`, `filterCameras(list: Camera[], q: string): Camera[]` (conserve l'ordre).

Table de correspondance fabricant → marque (sous-chaîne insensible à la casse du nom IEEE) : `axis communications` → `(Axis, "Axis")` ; `hikvision` → `(Hikvision, "Hikvision")` ; `dahua technology` → `(Other, "Dahua")` ; `uniview` → `(Other, "Uniview")` ; `hanwha vision` / `hanwha techwin` → `(Other, "Hanwha")` ; `vivotek` → `(Other, "Vivotek")` ; `mobotix` → `(Other, "Mobotix")` ; `avigilon` → `(Other, "Avigilon")` ; `bosch security` → `(Other, "Bosch")`. Tout autre fabricant → `None` (ce n'est pas une caméra, on ne l'affiche pas).

Règles de recherche : requête nettoyée de `: - . espaces` et passée en majuscules ; une caméra correspond si la requête nettoyée est contenue dans sa MAC sans séparateurs, ou dans son n° de série nettoyé de la même façon, ou si la requête brute est contenue dans l'IP ou le modèle (insensible à la casse). Requête vide → tout.
