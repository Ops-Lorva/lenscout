## Décisions de Benjamin (13-14/11) — ne pas rediscuter

- **Comptes : plus de trousseau système.** Nom + identifiant + mot de passe dans un fichier JSON local ; identifiant et mot de passe **scellés avec une clé intégrée à Lenscout** (constante dans le code). C'est un verrou anti-lecture, pas un coffre : Benjamin connaît et accepte la limite (clé publique, code ouvert).
- **Export / Import sans aucune question** (ni phrase de passe ni mot de passe maître) : un fichier repris d'un backup se réimporte seul sur un PC neuf.
- Import : les comptes **identiques** passent sans question ; les **nouveaux** sont ajoutés ; pour un nom déjà présent **qui diffère** : Remplacer (défaut) / Garder les deux (nom suffixé « 2 », « 3 »…) / Ignorer.
- Au premier lancement de la nouvelle version, les comptes de l'ancien format (secret dans le trousseau) sont **repris automatiquement** dans le fichier. On **ne supprime pas** les entrées du trousseau (zéro perte).
- Lenscout déchiffre seul : choisir un compte pour une action envoie le bon identifiant/mot de passe, comme en v1.
- **Réglages** : nouvel onglet en dernier. Thème Clair / Sombre / Système (défaut Système) ; Langue FR / EN / ES (déplacée depuis le bas de la barre latérale) ; case « Journal de diagnostic » (remplace le fichier `debug` à créer à la main) ; Version.
- **IP libres** : dans les feuilles IP et IP en lot, zone « Adresses libres » : balayage ping + ARP du sous-réseau de l'interface choisie ; exclut caméras vues, IP du poste, passerelle, tout ce qui répond ; affichage en plages cliquables avec leur taille ; cliquer remplit Adresse IP / IP de départ ; en lot, la première plage assez grande pour les caméras cochées est pré-choisie ; une ligne : « Une adresse qui ne répond pas peut appartenir à un appareil éteint. »
- **Design v2** : celui de la maquette. Ne retirer aucune fonction existante.

## Global Constraints

- Toutes les contraintes de `docs/superpowers/plans/2026-11-13-lenscout-v1.md` § Global Constraints restent valables **sauf** : « les mots de passe vivent dans le trousseau » (remplacé par le fichier scellé) et « jetons CSS `--ep-*` repris de LanProbe » (remplacé par les jetons de la maquette v2).
- Le type `Secret` reste : pas de `Serialize`, `Debug`/`Display` = `***`. Le fichier ne contient **jamais** un identifiant ou un mot de passe en clair ; les journaux non plus.

- Écritures de fichiers d'app : atomiques (temp + rename), comme `AccountBook::write` aujourd'hui.

## Review Focus

- Fichier de comptes de l'ancien format avec trousseau **inaccessible** au démarrage : l'app démarre, les comptes restent listés avec « Mot de passe à ressaisir », et rien n'est écrasé.
- Fichier d'import **corrompu, tronqué ou d'un autre logiciel** : erreur d'une ligne, aucun compte modifié.
- Import où « Garder les deux » produit un nom déjà pris (« Mairie Arles 2 » existe) : suffixe suivant libre.
- Sous-réseau plus grand qu'un /24 (/16) : le balayage est borné (≤ 1024 adresses autour de l'IP du poste) et le dit.
- Feuille fermée pendant un balayage : le balayage s'arrête, aucun événement ne vise une feuille disparue.

### Tâche 1 : Comptes scellés dans le fichier, reprise du trousseau, export/import (core)

**Files :** Modify `crates/lenscout-core/src/accounts.rs`, `crates/lenscout-core/Cargo.toml`, `Cargo.lock` ; Create `crates/lenscout-core/src/seal.rs` ; Modify `crates/lenscout-core/src/lib.rs`.

**Interfaces :**
- `seal.rs` : `pub fn seal(plain: &[u8]) -> String` (XChaCha20-Poly1305, clé `const KEY: [u8; 32]` intégrée, nonce aléatoire 24 o, sortie `base64(nonce || ciphertext)`) ; `pub fn open(sealed: &str) -> Result<Vec<u8>, SealError>`.
- Fichier comptes v2 : `{"version":2,"accounts":[{"id","name","login":"<scellé>","password":"<scellé>"}]}`. Lecture de l'ancien format (sans `version`, `login` en clair, secret au trousseau) → reprise : secret lu via l'ancien `SecretStore`, réécriture v2 ; si un secret manque, le compte garde un mot de passe vide marqué `needs_password` (affiché « Mot de passe à ressaisir ») — jamais d'échec de démarrage.
- `AccountBook` garde son API publique (`list`, `create`, `update`, `remove`, `credentials`, `has_secret`) ; le `SecretStore` ne sert plus qu'à la reprise.
- Export : `pub fn export(&self) -> String` → `{"format":"lenscout-accounts","version":1,"accounts":[{"name","login":"<scellé>","password":"<scellé>"}]}` (sans ids, jamais de champ `needs_password` exporté : un compte sans mot de passe est exporté sans `password`).
- Import en deux temps : `pub fn import_plan(&self, data: &str) -> Result<ImportPlan, AccountError>` (`ImportPlan { items: Vec<ImportItem> }`, `ImportItem { name, kind: New | Identical | Differs { login_differs: bool, password_differs: bool } }`, sans aucun secret dans `ImportItem`) ; `pub fn import_apply(&mut self, data: &str, choices: &HashMap<String, Choice>) -> Result<ImportSummary, AccountError>` avec `Choice::{Replace, KeepBoth, Skip}` (absent ⇒ `Replace`). Le plan est recalculé à l'application (le fichier n'est pas conservé entre les deux appels).
- Nouveaux codes d'erreur : `import_invalid` (fichier illisible ou d'un autre format).

- [ ] Tests d'abord (`cargo test -p lenscout-core accounts seal`) : `seal_roundtrip`, `seal_is_randomized` (deux scellages diffèrent), `open_rejects_tampered`, `file_never_contains_login_or_password_in_clear`, `migrates_v1_file_from_store`, `migration_missing_secret_keeps_account_needing_password`, `migration_keeps_store_entries`, `export_then_import_on_empty_book_restores_all`, `import_identical_is_untouched`, `import_differs_default_replace`, `import_keep_both_picks_next_free_suffix`, `import_skip_changes_nothing`, `import_rejects_garbage_and_foreign_json` (aucun compte modifié), `credentials_after_reload` (le bon login/mot de passe ressort).
